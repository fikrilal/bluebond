## BlueBond v0.1.2

Patch release from real dual-boot mouse testing.

## Install

```bash
curl -LO https://github.com/fikrilal/bluebond/releases/download/v0.1.2/bluebond-0.1.2-x86_64-unknown-linux-gnu.tar.gz
curl -LO https://github.com/fikrilal/bluebond/releases/download/v0.1.2/bluebond-0.1.2-x86_64-unknown-linux-gnu.tar.gz.sha256
sha256sum -c bluebond-0.1.2-x86_64-unknown-linux-gnu.tar.gz.sha256
tar -xzf bluebond-0.1.2-x86_64-unknown-linux-gnu.tar.gz
sudo install -m 0755 bluebond-0.1.2-x86_64-unknown-linux-gnu/bluebond /usr/local/bin/bluebond
```

## Fixed

- Removes stale BlueZ `[PeripheralLongTermKey]`, `[SlaveLongTermKey]`, and `[RemoteSignatureKey]` sections during key sync.
- Adds `--target-windows-source-address` for manual apply flows where the device reconnects only when BlueZ has a record at the Windows-current address.

## Real-World Test Result

This release was validated against a dual-boot Lenovo Legion M600 Mouse case where Windows moved the current mouse bond to:

```text
C6:C0:FF:F1:FB:80
```

while Linux still had:

```text
C6:C0:FE:F1:FB:80
```

The successful recovery command shape was:

```bash
sudo bluebond apply --execute \
  --windows-root /mnt/windows \
  --target-device C6:C0:FE:F1:FB:80 \
  --windows-source-device C6:C0:FF:F1:FB:80 \
  --target-windows-source-address
```
